# AGENTS.md

Guidance for coding agents and contributors working in this repository.

## What this is

`ocis-agent` is an always-on personal agent for ownCloud Infinite Scale (oCIS): a Go
sidecar (`backend/`) next to oCIS plus an oCIS Web extension (`frontend/`, `web-app-agent`).

Design notes are maintained outside the repository, so this file and the code state
everything a contributor needs.

## Layout

- `backend/` Go module `github.com/owncloud/ocis-agent/backend` (`cmd/`, `internal/`)
- `frontend/` Vue 3 + TypeScript extension, built with `@ownclouders/extension-sdk`
- `docker-compose.yml` + `dev/` dev stack (oCIS + nginx TLS proxy), run from the repo root.
  The host port is `OCIS_DEV_PORT` (default 9200, set in `.env`), so the stack is at
  `https://localhost:$OCIS_DEV_PORT`. Changing it after the first start needs `docker compose down -v`.
  Demo user `einstein` / `relativity`; the extension manifest is served at `/assets/apps/agent/manifest.json`.

## Commands

- `make backend-vet backend-test` Go vet, gofmt check, unit tests
- `make frontend-test frontend-build` Vitest and the production extension build
- `make license-check` REUSE lint (must pass before every commit)
- `make dev-up dev-down` local oCIS stack (after the first `make dev-up`, `docker compose up -d` also works; a fresh clone first needs `dev/certs` and `frontend/dist`, which `make dev-up` creates, and creating them via a bare compose run leaves root-owned bind-mount directories on Linux); `make sidecar` runs the sidecar against the dev stack (dev master key and database persist in `backend/bin/data`; delete it to reset local state; never use that key outside local development); `make spike` runs a probe of app-token renewal, SSE events and WebDAV preconditions against the dev stack

## Conventions

- Test first. Every behavior change has a failing test before the code that fixes it.
- Go: standard library first, no cgo, errors wrapped with context and never containing secrets.
- Commits and PR titles are Conventional Commits (`feat:`, `fix:`, `chore:`, `docs:`,
  `refactor:`, `test:`, `ci:`, `perf:`; breaking changes use `!` or a `BREAKING CHANGE:`
  footer). The changelog is generated from them, so write subjects as changelog entries.
- Sign off (`git commit -s`) and GPG-sign every commit.
- Licensing is declared centrally in `REUSE.toml` (Apache-2.0). Do not add per-file headers.
  There is no hand-written changelog file.
- A local oCIS checkout (if present) is a read-only reference; never modify it.

## Invariants (do not break)

1. The sidecar's HTTP API lives under `/agent-api/`. Never serve or route `/agent/`: those
   are the extension's UI routes and must reach oCIS Web.
2. The approval gate and all policy are enforced server-side, in Go, from the database.
   File contents, file names, memory, connector output and model text are untrusted data;
   no text may change policy, and destructive or outward actions always need approval.
3. `AGENT_MASTER_KEY` (base64, 32 bytes) comes only from the environment. The sidecar refuses
   to start without it. Never log, print or commit app tokens, the master key or LLM keys.
4. The sidecar talks to oCIS only through public HTTP APIs (Graph, WebDAV, auth-app, SSE).
   No changes to oCIS itself.
5. Approvals, policy changes, enrolment, incident revoke and unenroll require the user's OIDC token,
   never the agent's app token. Only renewing or rotating the agent's own token may use the app token.

## Verified oCIS behaviour (measured on the dev stack; identical on oCIS 8.2.1 and 9.0.0-rc.1, the pinned tag)

- `POST /auth-app/tokens` authenticated with an app token itself succeeds and returns a usable new token, and tokens are
  independent (deleting one leaves the others valid). A stolen token can therefore renew itself whatever the sidecar does.
- Policy for v1: the sidecar renews its own token in the background (below 50% of the TTL, default `AGENT_TOKEN_TTL`
  72h): create with the current token and a unique label `ocis-agent-<instanceId>-<nonce>`, verify with Graph `/me`, swap
  transactionally, then delete the old token. Safeguards: unenroll deletes every token with this instance's label prefix;
  a separately confirmed incident revoke deletes all of the user's app tokens; every sweep lists the tokens
  and pauses the agent (`token_anomaly`) on an unknown token with our prefix; the agent pauses itself (`dormant`) when
  the user has not been seen for `AGENT_DORMANCY_DAYS` (default 30). Never log or audit token or hash values.
- `DELETE /auth-app/tokens?token=` needs the hash returned in the `token` field of `GET /auth-app/tokens` (find it by
  label and created date), not the plaintext token (plaintext gives 500); with the hash it returns 200 and the token then gets 401. An already-deleted or unknown hash also returns 500 (not 404), so confirm a delete via the token list.
- The SSE endpoint `/ocs/v2.php/apps/notifications/api/v1/notifications/sse` accepts app-token Basic auth and emits
  `folder-created`, `postprocessing-finished` (upload), `item-renamed` (move) and `item-trashed` (delete) for the
  user's file operations; the data carries ids and etag but no path. Polling is the primary file-change trigger in v1; SSE only speeds it up.
- WebDAV preconditions: `If-None-Match: *` on PUT is ignored (204, the file is overwritten); `If-Match` on PUT is
  enforced but returns 409 (treat 409 and 412 as conflict); `If-Match` on DELETE is ignored (204); `Overwrite: F` on
  MOVE and COPY is enforced (412).
- Decision: write tools stat before creating and refuse if the target exists, and `files.delete` PROPFINDs and compares
  the ETag to the approved one itself before deleting (deletes go to the oCIS trash); the remaining race window is an
  accepted residual risk.
- Decision: no new notification channel (no email, webhook or oCIS notification hack). When the agent pauses itself, the
  reason is surfaced only inside the extension (status endpoint, banner, audit log).
- oCIS has no per-user notification create API (only admin or secret gated global notifications).

## Persistence

- Operational state lives in SQLite (`internal/store/sqlite`, pure Go) behind `store.Store`; `ocis-agent migrate` applies the embedded migrations, and start-up does too. Behaviour is specified by the suite in `internal/store/storetest`; a new store implementation must pass it unchanged.
- The audit log is append-only and hash-chained per user (`internal/audit`). Never UPDATE or DELETE `audit` rows; a database trigger rejects it. Known limit: `VerifyAudit` cannot detect removal of the tail of a user's chain; anchoring the chain head outside the database is future work. Add events with `Tx.AppendAudit` in the same transaction as the state change they describe.
- Job leases: one running job per user. Every worker write (`SaveCheckpoint`, `AppendStep`, `RenewLease`, `ReleaseJob`) carries the lease fence, which only grows and is kept after release or reap. A voluntary release (back to queued or waiting_approval) refunds the attempt, so attempts count crashes, not approval pauses. Treat `ErrFenceLost` as "stop working on this job now".
- Secrets are sealed with `internal/secrets` (AES-256-GCM, per-use nonce, DEKs wrapped by the master key from `AGENT_MASTER_KEY`). Pass a domain-separated `aad` such as `app_token:<user id>` (not the bare user id) so a ciphertext cannot be moved to another context. Never store or log token values, DEKs or the master key.
- `InTx` and `View` are not re-entrant: never call the store, `secrets` or `queue` from inside the callback (seal before the transaction). Start-up calls `secrets.Init`, so a wrong master key fails fast.
- Errors: input validation failures match `store.ErrInvalid` (map them to client errors); `store.ErrExpired` means an approval was decided after it expired.
- Approvals leave `pending` only through `DecideApproval` (the user's decision; it checks expiry and the arguments hash) or `ExpireApprovals`. The worker moves them with `TransitionApproval` (compare-and-swap on the legal edges only). A job waiting for approval resumes with `ResumeJobIfSettled` once nothing is pending; approved actions are executed after it resumes.
- Execution protocol for side effects: transaction A = `AssertLease` + approval approved->executing + `BeginIdempotent`; make the call outside any transaction; transaction B = `AssertLease` + `FinishIdempotent` + approval executed/failed/unknown + `AppendAudit` + `AppendStep`. A record still `started` after a crash means the outcome is unknown: reconcile it (`ListStartedIdempotent`) and never re-run blindly.
- Same-transaction rules: `InsertApproval` with `ReleaseJob(waiting_approval)`; `DecideApproval` with its `approval_decided` audit event and `ResumeJobIfSettled`; `ExpireApprovals` with `ResumeJobIfSettled` for every returned ref (refs are returned once, so a split strands the job). Idempotency keys are server-derived (job id, call id, args hash), never user-supplied.
- `Job.Runs` counts every claim and is never refunded; a runner must cap it and release to queued with `RequeueJob` and a delay.
- Model preference: `Policy.Models` maps a task kind (`store.ModelTaskChat`, `store.ModelTaskProactive`; `store.ModelTaskFor(trigger kind)`) to a model id. The store only checks the id's shape, so the API must check `llm.Catalog.Has` when setting one and the runner must use `Catalog.Resolve`. Always start from `GetPolicy` when changing a policy: a `Policy` built from scratch and put clears the preferences.
- Pause: the user's own pause is sticky; automatic reasons are ranked (`PauseSupersedes`); `ClearPause` clears only the reasons the caller names; queued jobs of a paused user are not claimed.

## oCIS access and memory

- `internal/ocisclient` is the only code that talks to oCIS. Every call takes a `Creds` (`AppToken(loginName, token)` or `Bearer(oidc)`); credentials, token values and token hashes are `Secret` values that print as `[redacted]`. `Creds` holds its secret behind a pointer, but a bare `Secret` in an unexported struct field still prints in clear, so hold credentials as `Creds`. Errors carry method, URL path and status only, never query strings or bodies, and redirects are not followed. Use `errors.Is` with its sentinels (`ErrNotFound`, `ErrPrecondition`, `ErrExists`, ...). The login name for Basic auth is Graph `onPremisesSamAccountName`, not the user id.
- oCIS quirks live in `ocisclient` and `ocisclient/fakeocis` (an in-memory oCIS with the same quirks and fault injection): `Put` with `If-Match` maps 409 or 412 to `ErrPrecondition` (a 409 without it is `ErrNotFound`, a missing parent), `Get`/`Put` fail closed when oCIS sends no ETag, `Move`/`Copy` never overwrite, `Delete` ignores `If-Match`, and `DeleteToken` takes the listed hash; callers confirm the delete through `ListTokens` (an already-gone hash is a 500). Tests of tools and memory use `fakeocis`; add a quirk to the fake whenever a new one is measured.
- Credentials (`internal/auth`): `Validator` accepts a bearer only if oCIS itself accepts it (Graph `/me`, cached 60s, also capped by the token's `exp`); `User.Name` is the LOGIN name (Basic auth needs it). A new token's label is recorded (`AddTokenLabel`) BEFORE the create request and the swap transaction never adds it again; a refused create (401/403) closes its label, an UNCERTAIN failure (timeout, 5xx, lost response) that finds no token keeps it open (it may still land). `Renew` deletes the old token only after the new one is verified and stored; `Enroll` deletes superseded tokens right after its commit. `Sweep` flags (`token_anomaly` pause; audit holds the COUNT only, never labels) a token with our prefix whose label is unrecorded, recorded-and-closed, or a second token under the current label, and never deletes those automatically; it deletes orphans (open, non-current labels with a live token) at once and closes open labels with no token only after a 5-minute grace. `Enroll`, `Revoke`, `RevokeAll` (incident) and `Unenroll` take the user's bearer; the caller derives `userID` from the validated bearer and the revoke functions verify with Graph `/me` that the bearer belongs to `userID`; renewal and the sweep use the app token, never the bearer. Confirm a delete by listing again (an unknown hash is a 500). Call `HandleUnauthorized` when oCIS answers 401 for the app credentials (it re-checks the stored credentials with Graph `/me` and does nothing for a still-working token), `Seen` on every authenticated user request (clears only the dormant pause), and `RenewDue`, `Sweep` and `PauseDormant` from the scheduler (renewal and the sweep also run while the agent is paused).
- Approvals (`internal/approvals`): `Gate.Classify` decides from the tool's declared `Risk` and the call's arguments only (reads and memory writes run, everything else needs an approval, anything refused by the tool or invalid is denied; `auto_approve_write` is never read; raw arguments are capped before parsing). It returns the CANONICAL argument bytes, their hash and the idempotency key. `Request` refuses duplicate call ids, re-verifies hash, tool, key and risk (`ErrBadCall`) and re-counts the per-job cap (live approvals only, `ErrActionLimit`, `MaxActionsPerJob` <= 500) in its transaction; `Request`, `Decide` and `ExpireAndResume` are single transactions together with releasing or waking the job and the audit events; a decision on an ended job is `ErrJobEnded`. `Decide` must get the OIDC subject of the authenticated user as `decidedBy`. `Run`, `RunAuto` and `RunRead` recompute hash, key and risk before running: `Run` refuses a mismatch with `ErrTampered`; `RunAuto` and `RunRead` return `ErrBadCall` for a key, tool or risk mismatch and `ErrTampered` only for the hash. `Run`/`RunAuto` are transaction A (lease, approval approved->executing, idempotency begin), the external call, transaction B (finish record, approval, audit, step); an existing record or an executing approval is reconciled via the tool, never run blindly; an unknown outcome is stored as idempotency failed with `{"outcome":"unknown"}` and the approval `unknown`. For a record left by an earlier attempt, a Retry verdict is honoured only after `Config.RetrySettle` (2 min) since it started, otherwise the outcome is unknown. A call interrupted by a cancelled ctx after transaction A (outcome not known) stays open (record started, approval executing): the next `Run` or `RunAuto` of the still-active job reconciles it, and `ReconcileOrphans` (called by the scheduler; it filters ended jobs itself, clamps `olderThan` to now minus `RetrySettle`, so pass now minus at least the longest call plus `RetrySettle`) covers ended jobs and never executes (Retry becomes failed, "not run"; a 401 stays in `Errors` with the record open). A lost lease still records the known outcome, returns a nil error and writes no step. Every effectful tool must be idempotent at the tool level or return Unknown (never Retry) from `Reconcile`. On `ErrNotApproved` from `Run` the runner re-reads the approval: terminal means call `Run` once more for the stored outcome, rejected means report it to the model as rejected, pending is a bug. `Outcome.Err` and errors from `Classify`/`RunRead` may match `ocisclient.ErrUnauthorized`: report them to `auth.HandleUnauthorized`; they are never shown to the model. The runner derives call ids from its own step sequence and runs tool calls of a job one at a time.
- Tools (`internal/tools`): a tool has `Prepare` (validate, preview, `TargetETag` of an existing target; no side effects), `Execute` (the call, with the approved `TargetETag`) and, if it has side effects, `Reconcile` (after a crash: Done, Retry, Failed or Unknown). Tools report a `Risk` and never decide policy; they get an `Env` built on the server (plain personal-drive id, credentials, budgets), so no argument can name a drive or user, and unknown JSON fields are errors. `parse` and `Canonicalize` also reject duplicate or case-variant JSON keys at any depth, non-object arguments, nesting deeper than 32 and objects with more than 256 keys, and `cleanPath` rejects control, line-separator and bidi characters, so what executes is what was approved; `ArgsHash` and `IdemKey` are computed only in `internal/tools`, and the gate must cap the raw argument size before parse or hash. Anything read from oCIS goes into `Result.Blocks` (untrusted, to be fenced), never into `Summary` or refusal text (refusal texts may echo model-supplied paths unfenced: model output, not file data); treat `Result.Diff` as untrusted too. Write tools refuse the root and every `memory.IsReserved` path (source and destination) in `Prepare` and `Execute`; overwrite sends `If-Match` with the approved ETag, delete compares the ETag itself. `memory.read` stats before reading and calls `memory.Service.Forget` if its content cannot be handed to the model, because a cached ETag unlocks `memory.write` replace: the runner must `Forget` every `memory.read` result that never reaches the model (a `RunRead` error, a failed save, a truncated block), and only the job runner may call the memory tools. `memory.write` is auto-allowed (no approval screen), so the runner must record its `Result.Diff` in the activity feed. A 401 from oCIS is returned wrapped: report it to `auth.HandleUnauthorized`.
- LLM (`internal/llm`): `Provider.Complete` takes a validated `CompletionRequest` (dotted lower-case tool names, which the OpenAI client maps to `__` on the wire) and returns the model's message, `Usage` and a `StopReason`; tool-call `Arguments` stay a raw string for the gate. Treat everything it returns as untrusted. Never act on a `StopLength` response's tool calls (arguments may be cut off). Before a decoded assistant message goes back into the transcript, rewrite every `ToolCall.ID` to the runner's own transcript-unique id (the client invents `call_<i>` per response and `Validate` refuses duplicate ids). Provider errors are sentinels without bodies, URLs or keys: `llm.Retryable` (rate limit, outage) means requeue with a delay, `ErrAuth`, `ErrRejected`, `ErrMalformed`, `ErrTooLarge` and `ErrInvalid` do not, a cancelled context is a context error. The client only talks to the one configured https base URL (http only for loopback), never follows redirects, and checks the host allow-list. Keys are `llm.Secret`. Models: the operator's `llm.Catalog` (`AGENT_LLM_MODEL` default plus `AGENT_LLM_MODELS`) lists what users may choose; a user's choice per task kind is `Policy.Models` (`store.ModelTaskFor(job.TriggerKind)` picks the kind) and the runner must pass it through `Catalog.Resolve` before setting `CompletionRequest.Model`; an API that sets it must check `Catalog.Has`. `AGENT_LLM_*` are optional until the worker role needs them; `llmtest.New` scripts a provider for tests.
- Memory (`internal/memory`) is untrusted data under `/.ocis-agent/memory/`. `Write` of an existing file needs a prior `Read` (cached ETag per user, `ErrNotRead`) and fails with `ErrConflict` if the user edited it meanwhile; a file the user deleted drops its cached ETag on `Read`, so `Write` can recreate it. The ETag cache is per user and spans jobs, not per reader (known limit; the real fix is a base ETag for `Write` or a per-job cache): only the job runner may use `Read`. The memory excerpt and UI/API reads use `Peek`, a non-caching `Read` (same names, limits, text check and errors; never stores or drops an ETag, so no `Forget` is needed): seeing a file in the excerpt never unlocks a replace, which always needs the model's own `memory.read`. `Append` re-reads and retries. File tools other than `memory.*` must refuse paths for which `memory.IsReserved` is true (path-only: address the personal drive by its plain id, and check both source and destination of MOVE/COPY). Pass a `Budget` per job to cap memory writes, and record `Change.Diff` in the activity feed.
- Agent runner (`internal/agent`): `Runner.Run` runs one claimed job. The checkpoint is the transcript (the Goal as the first user message; over 1 MiB the job fails), and every provider call id is rewritten to the runner's own `c<N>`. At claim `Job.Runs` over `MaxRuns` fails the job; before every model turn come the step limit and the prechecks from the database, in order: kill switch (requeue at claim, else cancel), pause (requeue), credentials (invalid fails; fresh ones replace the env's), `DailyTokens` (0 = unlimited; reached fails; the day resets at UTC midnight and one model call may overshoot it). Kill switch, pause and credentials are checked before every model turn and every tool call; a running call is not interrupted and its batch's remaining approvals stay `approved` for the next claim. The model is `Catalog.Resolve` of the policy's choice for `ModelTaskFor(trigger)`; the system prompt carries the fenced `Peek` excerpt of `profile.md` and `projects.md`. `processCalls` is idempotent per call id and handles fresh turns, approval resumes and crash resume: read -> `RunRead`, memory write -> `RunAuto` (its diff audited as `memory_changed`), approve -> one `Gate.Request` batch at the end of the turn (over the action limit the whole batch is denied), deny -> refusal text plus a `policy_denied` audit event. Job errors and audit details are fixed `Reason*` constants, never provider or oCIS text. Env budgets (reads, memory writes) are per job and fresh per claim. `Run` returns nil once it released the job and an error while the job may still be running (lost lease or conflict wrapped, a context error as is, anything else the caller requeues). The Goal reaches the model as the user's own instruction, so goals of proactive jobs must never embed file names or other untrusted text. Live approvals of a job that ended stay until a follow-up settles them.
- Worker (`internal/agent`): a `Worker` claims one job at a time and renews its lease every third of the queue's TTL (it takes the period from `Queue.LeaseTTL`; a renewal error other than a lost lease is retried, but a whole TTL without a successful renewal counts as lost). A lost lease cancels the job's context; shutdown requeues the job after `Config.ShutdownRequeueDelay` (keep it >= `approvals.Config.RetrySettle`, default both 2m); a panic or another runner error requeues with backoff until the runs cap, then fails it; while the kill switch is on it claims nothing; it logs ids and fixed outcomes only. `RunPool` runs n workers. Scheduler and API wiring (`ExpireAndResume`, `ReconcileOrphans`, token renewal and the sweep, `Seen`, the kill-switch setter `SetKillSwitch`) is separate.
